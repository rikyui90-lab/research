# Web ページのデザイン指針

Web ページを作る・直すときの物差し。10 個の公開ガイドラインを読んでまとめた(2026-10-10)。株クイズ(カブレベル)をはじめ、このリポジトリのページはこの指針に従う。

## 1. 使う人の言葉で、見えるようにする

- 状態は、すぐ知らせる。操作したら、すぐ反応を返す。(NN/g #1)
- 内部の言葉ではなく、使う人の言葉で書く。見出しやリンクは、中身が分かる言葉にする。「ここをクリック」「もっと見る」だけにしない。(NN/g #2、ホームページ指針)
- 覚えさせずに、見て選べるようにする。(NN/g #6)

## 2. 間違えても戻れる。間違えにくくする

- 「非常口」をはっきり出す。取り消し、やり直し、キャンセルを用意する。(NN/g #3)
- 間違いは、起きる前に防ぐ。費用の大きい間違いから先に防ぐ。(NN/g #5)
- エラーは、平易な言葉で、何が起きたかと直し方を示す。目立つ見た目にする。(NN/g #9)

## 3. 一貫性と慣習

- 同じものは、同じ名前・見た目・位置にする。ほかのサービスの慣習にも合わせる。(NN/g #4、W3C、GOV.UK)
- ナビゲーションは、ページが変わっても、名前・見た目・位置をそろえる。今どこにいるかが分かる手がかり(見出し、パンくず)を置く。(W3C)

## 4. 余計なものを減らす

- 関係のない情報は、必要な情報の目立ちを下げる。(NN/g #8)
- グラフィックは、設計の最後に、ねらいに合わせて足す。文字の装飾(大きさ・色の種類)も減らす。(NN/g ホームページ指針)
- 同じ項目を何度も並べない。1 つしかないカテゴリや箇条書きを作らない。

## 5. アクセシビリティ(守る数値)

| 項目 | 基準 | 出典 |
|------|------|------|
| 文字と背景のコントラスト比 | 4.5:1 以上(大きな文字は 3:1) | WCAG 1.4.3、デジタル庁 |
| 枠線・ボタンの輪郭などの、文字ではない部品 | 隣り合う背景と 3:1 以上 | デジタル庁、WCAG 1.4.11 |
| 色だけで伝えない | 色に、記号・文字・数字を添える | WCAG 1.4.1 |
| 本文・UI の文字の大きさ | 16 CSS px 以上(14px 以下は、フッターなど狭い場所に限る) | デジタル庁 |
| 本文の行の高さ | 文字の大きさの 1.5 倍以上(1.7〜1.75 倍を推奨) | デジタル庁 |
| キーボード操作 | すべての部品に届き、フォーカスの印がはっきり見える | WCAG 2.4.7 |
| フォーカスの印 | 黄(Yellow-300)と黒の二重。色を変えない | デジタル庁 |
| 押せる部品 | 見た目で、押せると分かる。ホバー・フォーカス・押下で見た目が変わる | W3C |
| ラベル | 入力欄のすぐ近く(左か上。チェックボックスは右) | W3C |
| 画面の大きさ | 狭い画面・拡大表示でも読める。横スクロールを出さない | W3C、NN/g |
| 自動で動くもの(アニメ、音、カルーセル) | 止める操作を、見える場所に置く | W3C |
| 画像・動画 | 代わりの文章を用意する | W3C |
| 動き | OS の「動きを減らす」設定にしたがう | web.dev |
| 適合の目標 | WCAG 2.2 / JIS X 8341-3:2016 の **AA** | W3C、デジタル庁 |

## 6. 作り方の考え方

- **意味のある HTML を先に**。見出し、ボタン、リストなど、要素の意味どおりに書く。ARIA は、HTML で足りないときに補う。(web.dev)
- **色の役割を分ける**。プライマリー、セカンダリー、ターシャリー、背景色、共通色(灰色の階調)、機能色(リンク、フォーカス)に分け、役割ごとにコントラストを確かめる。(デジタル庁)
- **スタイル・部品・パターン**に分けて、再利用する。(GOV.UK、デジタル庁)
- 余白と見出しで、関係のあるものをまとめる。(W3C)
- 画面を作ったら、**ブラウザで開いて**、スマホ幅(375px)でも見る。キーボードだけでも操作してみる。

## 7. 読めなかった 2 つの、一般的な考え方(未確認)

- **Apple HIG**: 「明確さ」「敬意(コンテンツを引き立てる)」「奥行き」。タッチ対象は約 44pt 以上。文字の拡大(Dynamic Type)とダークモードに対応する。
- **Material 3**: 色の役割(primary、secondary、surface、on-〇〇)を決める。タッチ対象は約 48dp 以上。ホバー・フォーカス・押下は、重ねる色の濃さで表す。

## 作るとき・直すときのチェック

1. 文字は 16px 以上か。行の高さは 1.5 倍以上か。
2. 文字と背景は 4.5:1 以上か。枠線やボタンの輪郭は 3:1 以上か。(計算して確かめる)
3. 色だけで、意味を伝えていないか。
4. キーボードだけで操作でき、フォーカスの印が見えるか。
5. 押せる部品は、高さ 44px 以上か。
6. スマホ幅で、横スクロールが出ないか。
7. 動くものは、止められるか。「動きを減らす」設定にしたがうか。
8. 言葉は、使う人の言葉か。エラーは、直し方を示しているか。
9. 画像や図に、代わりの文章があるか。
10. 余計な飾りや、重複はないか。

## カブレベルでの適用(2026-10-10)

- 補足の文字を 16px にそろえた(補足の注記・チャートの目盛り・フッターなど、狭い場所だけ 13〜15px)。解説の本文の行の高さは 1.9。
- ボタンの枠線の色を、背景との比が 3:1 以上の色(`--border-ui`)にした。
- フォーカスの印を、黄と黒の二重にした。
- 押せる部品の高さを、44px 以上にした(難易度の切り替え、「トップに戻る」など)。
- すでに満たしていたもの: 文字のコントラスト比(本文 15.7:1、補足 7.5:1 ほか)、動きを減らす設定、`lang="ja"`、正解・不正解を文字でも表示、チャートの色(赤・青)と、文字による説明。
- 今後の課題: 陽線・陰線を、色だけでなく形(中空など)でも区別する。画面を切り替えたときの、フォーカスと読み上げの扱い。
