# 株クイズゲーム 設計書

作成日: 2026-10-06
状態: 設計承認済み(設計書のレビュー待ち)。用語クイズを120問に増やし、解説画面に「くわしく」欄を足した内容(v5)を反映済み。さらに、値動き予想のモードをなくし、チャートの形状の答え合わせでその後の値動きを見せる内容(v6)を反映済み。チャートの形を30種類から50種類に増やし、どの難易度にも10種類そろえた内容も反映済み。ローソク足も30種類から50種類に増やし、どの難易度にも10種類そろえた内容を反映済み

## 1. 目的

株の知識を学べるクイズゲームを、Web で公開して広く遊んでもらう。
チャートの形状(形の名前)、ローソク足、用語の3種類を出題する。チャートの形状の答え合わせでは、その形のあとの値動き(教科書的な傾向)も見せる。

### 決まっていること

- チャートはプログラムで生成する(実在の銘柄・実データは使わない)
- ランキングなし。スコアはブラウザの `localStorage` に保存するだけで、サーバーは使わない
- 作り方は単一 HTML(HTML + CSS + JavaScript + Canvas/SVG の1ファイル)
- 公開は GitHub Pages を想定するが、公開作業は本設計の範囲外(ユーザーが明示的に許可するまで行わない)

### 範囲外(作らないもの)

ランキング、ログイン、広告、課金、実データの取り込み、問題の自動配信。

## 2. 免責

「学習用のゲームです。実際の相場では必ずこの通りに動くとは限りません。投資の助言ではありません。」を全画面の下部に常時表示する。
答え合わせで見せる「この後の値動き」は「教科書的な傾向」であり、実際の相場の予測ではない。

## 3. ゲームの流れ

1. **スタート画面**: タイトル、難易度の選択、出題モードの選択、最高スコア
   - モード: 全部まぜ / チャートの形状 / ローソク足 / 用語
   - 難易度: すべて / ★ / ★★ / ★★★ / ★★★★ / ★★★★★ の6つ(出題モードと組み合わせて使う。選んだ難易度は、ページを開いているあいだ保つ。折り返して、スマホ幅でも横スクロールしない)
   - 各モードのボタンに、選んだ難易度での最高スコア・正解率・そのラウンドの問題数を表示する
2. **ラウンド**: 1ラウンドは最大10問。選んだモードと難易度に該当する問題からランダムに選ぶ(重複なし)。該当する問題が10問に満たない場合は、その数が1ラウンドの問題数になる(どの組み合わせも1問以上ある。用語は ★★★★・★★★★★ でも20問ずつあり、10問になる。チャートの形状とローソク足は、どの難易度にも10種類ずつあり、すべての難易度で10問になる。10問に満たない組み合わせが生じた場合も、「あるだけで出題」する)。つまり、1ラウンドの問題数は min(10, モード × 難易度の問題数) である
   - 「全部まぜ」では、チャートの各パターンが、チャートの形状の問題を1問ずつ出す(難易度で絞り込んだ場合は、その難易度のパターンだけ)
   - 観察(仕様の変更ではない): 用語が120問になったため、難易度が「すべて」の「全部まぜ」の候補は、チャートの形50 + ローソク足50 + 用語120 の220問で、約5割が用語になる。★★★★・★★★★★ の候補も、用語20 + ローソク足10 + チャートの形状10 の40問で、用語が5割を占める。出題の偏りを変えたい場合は、別の仕様変更として検討する
3. **1問ごと**:
   - 問題を表示する(チャートは Canvas または SVG で描く)
   - 4択で答える
   - すぐに解説画面を出す
   - 画面を描いた直後の400ミリ秒間は、クリックを無視する(ダブルクリックの2回目で、次の問題の答えや「次の問題へ」を誤って押さないため)
   - 問題画面と解説画面には、問題番号の横に難易度(★ から ★★★★★ まで)を表示する
   - 問題画面と解説画面の上部に「← トップに戻る」を置く。押すと画面の中に確認(「今のラウンドは途中でやめるよ。トップに戻っていい?」、ボタンは「やめてトップへ」/「続ける」)を出す。「やめてトップへ」を選ぶとそのラウンドを破棄してスタート画面に戻り、成績(最高スコア・正解率)は記録しない。確認を出している間は、選択肢や「次の問題へ」は答えとして扱わない。確認が開いた直後と閉じた直後の400ミリ秒間も、クリックを無視する
4. **解説画面**:
   - 正解の名前を大きく表示する(例:「ダブルトップ」)
   - 解説を1〜2行で表示する
   - 解説の下に「くわしく」欄を表示する(詳しくは「「くわしく」欄」を参照)
   - 不正解のときは「あなたの答え: ○○」を併記する
   - チャートの形状の問題では、解説の枠とチャートのあいだに「この後の値動き: 上がりやすい / 下がりやすい / 横ばい」の1行を出し、続きの値動きをチャートに点線で描く(問題を出している間は描かない)。三角持ち合い・拡大三角形・エリオット波動の推進5波(上昇・下降)は、抜ける方向や5波のあとの動きが抜けるまで(または見方によって)分からないので、「この後の値動き: 上下どちらに抜けるかは、抜けるまで分からないよ」と出し、点線は描かない(この文言は `OUTLOOK_LABELS.either` に持ち、画面は「この後の値動き: 」に `OUTLOOK_LABELS` の文言をつなげて出す)
   - 「次の問題へ」ボタン
5. **結果画面**: 正解数、間違えた問題の一覧(復習用。各行に難易度の星を付ける)、「間違えた問題だけやり直す」ボタン(間違いが1問以上あるときだけ)、もう一度ボタン、トップへ戻るボタン、結果のテキストコピー
   - 結果のテキストには、モード名に加えて難易度の星を含める(難易度が「すべて」のときは星を付けない。例: 「株クイズ(チャートの形状・★★)で 10問中7問正解!」)
6. **やり直し**: 「間違えた問題だけやり直す」を押すと、そのラウンドで間違えた問題だけで新しいラウンドを始める。
   - 問題とチャートは元のラウンドと同じ。選択肢の並びは入れ替える
   - 画面には「やり直し 問題 n / N」と表示する
   - やり直しのラウンドは、最高スコアにも正解率にも入れない。結果画面には、そのことを注記する
   - やり直しの結果でまだ間違えた問題があれば、「まだ間違えた問題をやり直す」で何度でも繰り返せる
   - やり直しの結果画面には「結果をコピー」を出さない。「新しいラウンドを始める」で通常のラウンドに戻る
7. **保存**: 最高スコアとモード×難易度ごとの正解率を `localStorage` に保存する。保存のキーは、難易度が「すべて」ならモード名そのまま、それ以外は `モード名:難易度`(`pattern:easy` など。内部の難易度の値は `easy` / `normal` / `hard` / `expert` / `master`)。難易度の指定がない古い保存データは「すべて」として読む

## 4. 問題の種類

| type | 内容 | チャート |
|------|------|----------|
| `pattern` | 完成したチャートを見せて、形の名前を4択で答える。回答後に、その後の値動き(`outlook`)を見せ、続きを点線で描く | あり |
| `candle` | 1〜5本のローソク足を見せて、名前を4択で答える | あり |
| `term` | 用語の意味を4択で答える | なし |

## 5. チャート生成

- パターンごとに「形の骨格」(山と谷の位置の並び)を定義する。
  例: ダブルトップ = 上昇 → 高値 → 押し → 同じ高さの高値 → 下落
- 骨格の点のあいだを、単調3次補間(PCHIP)でなめらかにつなぐ。点の数は120点(答え合わせで描く続きは30点)
- そこへ、なめらかなゆらぎ(AR(1) で作るノイズ)を足す
- 移動平均線は短期10・中期30・長期60の3本を計算する。ゴールデンクロス・デッドクロスと、2つのパーフェクトオーダーのチャートに付け、クロスは短期と中期の交差である。色は短期が橙、中期が緑、長期が紫で、線の右端に「短」「中」「長」の文字を添え、チャートの下に色の説明を書く(解説文は「中期」の移動平均線と書く)
- 乱数はシード付きの擬似乱数を使い、問題ごとにシードを持つ。同じシードなら同じチャートになる
- 描画は、点を曲線でつないだ折れ線(曲線描画)とローソク足の両方に対応する

### 価格の目盛り(チャートの形状)

チャートの形状の折れ線チャート(ローソク足は対象外)には、Yahoo!ファイナンスのチャートに近い見た目で、右端に価格の目盛り、各目盛りに薄い灰色の細い横の点線を引く(日付の軸はない)。

- 価格は架空である。相対値 v(0〜100)を、問題のシードだけで決まる `priceScaleFor(seed)`(`base` は300〜4000円ほどで10円刻み、`span` は `base` の15〜40%)で `toPrice(v) = base + v × span / 100` と読み替える。専用の乱数(`seed + 104729`)を使うので、チャートの形は変わらない
- 目盛りは `niceTicks(min, max)` で、縦軸の範囲の中に 1・2・5 × 10^k の刻みで3〜6本を選ぶ。文字は右端に右寄せで、3桁区切りの数字だけ(円記号なし)
- 縦軸の範囲は、答え合わせの続きを含めて決めるので、問題と答え合わせで目盛りは動かない。点線は折れ線より下に描く
- 「短」「中」「長」の名前は、折れ線の右端と目盛りの列のあいだに書き、目盛りの文字と重ならない
- チャートの下(問題の画面と答え合わせの画面)に「価格は架空の例だよ(目盛りは形を読みやすくするための目安だよ)。」と添える

### ローソク足の収録

50種類を収録する。当初の10種類に、次の10種類(第2弾)、さらに次の10種類(第3弾)、さらに次の20種類(第4弾)を加えた。

- 第2弾: 宵の明星、強気のはらみ足、弱気のはらみ足、毛抜き天井、毛抜き底、切り込み線、かぶせ線、トンボ、塔婆、コマ
- 第3弾: 下影陽線、上影陰線、上窓(ギャップアップ)、下窓(ギャップダウン)、強気のはらみ十字、弱気のはらみ十字、上げ三法、下げ三法、捨て子線(底)、捨て子線(天井)
- 第4弾: 陽の丸坊主、陰の丸坊主、四値同時線、陽の寄り付き坊主、陰の寄り付き坊主、三空踏み上げ、三空叩き込み、上放れ並び赤、下放れ並び黒、差し込み線、入り首線、行き違い線、陽の出合い線、陰の出合い線、陽のたすき線、陰のたすき線、上放れの星、下放れの星、赤三兵先詰まり、赤三兵思案星

第3弾の定義の要点は次のとおりである。

- 下影陽線 / 上影陰線: 1本。実体は値幅の 30〜50%、ヒゲは実体より長く、反対側のヒゲはほとんどない(ハンマー・流れ星より実体が大きい)
- 上窓 / 下窓: 2本。上窓は2本目の安値が1本目の高値より上、下窓は2本目の高値が1本目の安値より下に離れる(窓)
- 強気 / 弱気のはらみ十字: 2本。1本目の大きな実体の中に、2本目の十字線(始値と終値が同じ)が収まる。1本目は強気が陰線、弱気が陽線
- 上げ三法 / 下げ三法: 5本。1本目の大きな実体のあと、小さな実体の3本が1本目の値幅の内側で少しずつ逆向きに動き、5本目が1本目の終値を超えて引ける
- 捨て子線(底 / 天井): 3本。十字線が前後の足と、どちらも窓を空けて孤立する(底は下に、天井は上に)

### 紛らわしい選択肢の組

名前が似ている・見た目が近い組は `CONFUSABLE_PAIRS` に定義する(例: 三角持ち合いとペナント、十字線とトンボ・塔婆、毛抜き天井とかぶせ線)。新しい項目では、見た目が近い組(窓を含む星と捨て子線、はらみ足とはらみ十字、ハンマーと下影陽線、パーフェクトオーダーとゴールデン/デッドクロス・チャネル、ダイヤモンドと対称三角形・三尊など)を足した。追加の20種類のチャートの形にも、形ごとに見た目が近い組を足した(ボックス上抜け・下抜けとボックス圏・三角形、ダマシとボックスの抜け・ダブルトップ/ボトム、三角保ち合いの上放れ・下放れと三角持ち合い・三角形・ペナント、エリオット波動とパーフェクトオーダー・チャネル・N字、ウェッジの上抜け・下抜けとウェッジ・旗形・三角保ち合い、チャネルの下抜け・上抜けとチャネル・ウェッジ、セリングクライマックスとVボトム・ウェッジ・ソーサーボトムなど。確認(v6)でさらに14組を足した: ボックス下抜け・上抜けとトリプルトップ・ボトム、ダマシとトリプルトップ・ボトム、ダマシとリターンムーブ、エリオットのサイクルとチャネル・ウェッジの抜け、セリングクライマックスと丸天井・パーフェクトオーダー、三角保ち合いの上放れ・下放れとボックスの抜け。追加した組は全部で85組で、チャートの形どうしの組は計109組になった)。追加の20種類のローソク足にも、見た目が近い組を足した(丸坊主と大陽線・大陰線、寄り付き坊主と流れ星・ハンマー・上影陰線・下影陽線、三空と窓・赤三兵・黒三兵、並び赤・並び黒と窓・赤三兵・黒三兵、差し込み線・入り首線・出合い線と切り込み線・包み足・はらみ足、たすき線と包み足・切り込み線・かぶせ線、放れの星と明けの明星・宵の明星・窓・コマ、赤三兵の先詰まり・思案星と赤三兵・上窓など。確認(v6)でさらに3組を足した: 行き違い線とたすき線、差し込み線・入り首線と毛抜き底。追加した組は全部で64組で、ローソク足どうしの組は計97組になった)。選択肢を作るときに、正解と紛らわしい組になるものを、間違いの選択肢の候補から除外する。除外するのは「正解の項目と紛らわしい組」だけなので、間違いの選択肢どうしが紛らわしい組になることはありうる(4つの選択肢全体で、紛らわしい組が同時に並ばないことまでは保証しない)。

### 難易度

難易度は5段階で、画面には ★ / ★★ / ★★★ / ★★★★ / ★★★★★ とだけ表示する(内部の値は `easy` / `normal` / `hard` / `expert` / `master`。絞り込みの「すべて」は `all`。読み上げ用の説明は「難易度 星Nつ(5段階)」)。スタート画面の切り替えは「すべて」と5段階の6つである。

- チャートのパターン、ローソク足、用語のすべてに難易度を付ける。個数は次のとおり(種類ごと)

| 難易度 | 用語 | ローソク足 | チャートの形 |
|--------|------|------------|--------------|
| ★ | 27 | 10 | 10 |
| ★★ | 27 | 10 | 10 |
| ★★★ | 26 | 10 | 10 |
| ★★★★ | 20 | 10 | 10 |
| ★★★★★ | 20 | 10 | 10 |
| 計 | 120 | 50 | 50 |

- 「全部まぜ」は、用語・ローソク足・チャートの形状の合計が候補になる(★ と ★★ は 27 + 10 + 10 = 47問、★★★ は 26 + 10 + 10 = 46問、★★★★・★★★★★ は 20 + 10 + 10 = 40問)。どの難易度でも1ラウンドは10問になる
- 各難易度には、v4 の追加分として、次の8問が入っている(用語4 + ローソク足2 + チャートの形状2)。この8問は、v5 で用語を足しても変わらない

| ★ | 配当、株主優待、上場、単元株 | 下影陽線、上影陰線 | 上昇チャネル、下降チャネル |
| ★★ | 損切り、利益確定、ナンピン、塩漬け | 上窓、下窓 | Vボトム、Vトップ |

新しいチャートの形の定義の要点は次のとおりである。

- 上昇チャネル / 下降チャネル: 平行な右上がり(右下がり)の2本の線のあいだで、高値と安値を切り上げ(切り下げ)ながら上下に振れる
- Vボトム / Vトップ: 急落(急騰)のあと急反発(急落)し、底(天井)が尖っている。丸底・丸天井ではない
- 上昇 / 下降パーフェクトオーダー: 移動平均線(短期10・中期30・長期60)が、上から 短期 > 中期 > 長期(下降は長期 > 中期 > 短期)の順に並び、3本とも右上がり(右下がり)になる。移動平均線つきで、凡例を出す
- ラウンドトップ: ゆるやかに上がって丸い天井をつけ、ゆるやかに下がる。山が1つで、左右がほぼ対称
- 逆カップウィズハンドル: 丸い山のあと、小さな戻り(取っ手)を作る、カップウィズハンドルの上下を逆にした形
- ダイヤモンドトップ / ボトム: 高値圏(安値圏)で値幅が広がってから狭まり、ひし形を描いて、下(上)に抜ける

### 答え合わせで描く続きの生成

パターンの `outlook` の方向へ動く値動き(30点)を、ノイズつきでランダムに生成する。
方向は必ず `outlook` と一致させる(チャートが答えと矛盾しないようにする)。`outlook` が `either` のときは続きを作らない(空の配列)。

続きは問題を出している間は描かず、答え合わせのときだけ点線で描く。縦軸の範囲は、続きを含めた値と、続きを最後の値で上下に折り返した値から決めるので、軸は方向を示唆せず、答え合わせで動かない。

## 6. 問題データ

問題は1つの配列にまとめ、1問ごとに次の項目を持つ。

- `type`: `pattern` / `candle` / `term`
- `id`: 一意の文字列
- `difficulty`: `easy` / `normal` / `hard` / `expert` / `master`
- `pattern`: パターン名(`pattern` のみ)
- `seed`: チャート生成のシード(チャートのある問題のみ)
- `question`: 問題文
- `choices`: 選択肢(4つ。正解を1つ含み、重複しない)
- `answer`: 正解の選択肢
- `explanation`: 解説(1〜2行)
- `detail`: 「くわしく」の文(必須。`validateQuestion` は、`detail` が無い、または空の問題を不備として見つける)
- `outlook`: `up` / `down` / `flat` / `either`(`pattern` のみ。答え合わせで見せる値動き)
- `category`: `term` / `technical`(データの項目にだけ持つ。v5 で追加した用語80問が持ち、用語50問が `term`、テクニカル30問が `technical`。出題の動きは変えない。既存の40問には付けない)

選択肢の並び順は、出題のたびにシャッフルする。
`pattern` の問題は、パターン定義から自動で作る。
`candle` と `term` の問題は、手で書いたデータを入れる(`candle` 50問、`term` 120問。`term` は、既存の40問に、v5 で足した80問を加えたもの)。

### 「くわしく」欄

- 解説画面で、解説の下に「くわしく」という見出しの枠を出し、`detail` の文を表示する。解説よりも踏み込んで、なぜそうなのか・実際にどう使われるか・注意点(ダマシや勘違い)を2つ以上書く
- 文章は120〜250字・2〜4文で、句点で終える。解説と同じ内容を繰り返さない。「必ず」「絶対」「買うべき」「売るべき」のような断定や助言の言葉は使わない。220項目で、すべて違う文にする
- チャートの形(50)の `detail` は、パターン定義に1つ持つ。そのため、形そのものの説明にし、特定の問題を指す言い方(「正解」「この問題」)は使わない。ローソク足(50)も同じ
- 既存の100項目(チャートの形30・ローソク足30・用語40)の `detail` は、データのブロックの表 `DETAIL_BY_ID`(形・ローソク足・用語に分けた表)に持ち、`assignDetail` で各項目に付ける(`DIFFICULTY_BY_ID` と `assignDifficulty` と同じ作り)。表にない項目には付かず、`validateQuestion` が不備として見つける。追加の用語80問と、追加のチャートの形20種類と、追加のローソク足20種類は、`TERMS`・`PATTERNS`・`CANDLE_PATTERNS` の各項目に `detail` を直接書き、`DETAIL_BY_ID` には入れない
- 文章は、証券会社・取引所などの解説ページを読んで、自分の言葉で書き直したもので、出典の文を写していない。内容の出典の URL は `docs/superpowers/sources/2026-10-09-quiz-sources.md` に記録している(出典の URL は画面には出さない)

## 7. ファイル構成

- 配置: `stock-quiz/index.html`(既存の不祥事ページとは混ぜない)
- `index.html` の中のコードを3つのブロックに分ける。
  - **データ**: 問題データ、パターン定義

## 8. テスト

- ロジックの単体テストは `stock-quiz/tests/logic.test.js` に置き、Node 標準の `node:test` で動かす(外部パッケージは使わない)。
- テストは `index.html` を読み込み、`DATA-START` と `DATA-END` のあいだ、`LOGIC-START` と `LOGIC-END` のあいだ(データとロジックのブロック)を取り出して評価する。
- 確認する内容:
  - 同じシードなら同じチャートが生成される
  - 価格の目盛り: `priceScaleFor` が同じシードなら同じ値で、シードだけで決まり(系列の乱数を変えない)、`toPrice` が単調で正になる。`niceTicks` が 1・2・5 の刻みで、昇順・範囲内・3〜6本で、幅が0でも壊れない
  - チャートの続きの値動きの方向が `outlook` と一致する(`either` は空)。形状の問題が `outlook` を持つ。`outlook` のモード・問題の種類がどこにもない
  - すべての問題で、選択肢が4つで重複がなく、正解が1つだけ含まれ、難易度が正しい値である
  - 全パターンに骨格と `outlook` が定義されている
  - 1ラウンドの問題に重複がない。1ラウンドの問題数が、モード × 難易度のすべての組み合わせで min(10, 該当する問題数) になり、どの組み合わせも1問以上ある(期待値は、チャートの形状が 10 / 10 / 10 / 10 / 10、ローソク足が 10 / 10 / 10 / 10 / 10、用語が 27 / 27 / 26 / 20 / 20)。「全部まぜ」の候補は 47 / 47 / 46 / 40 / 40 問で、どの難易度でも1ラウンドは10問になる
  - 各難易度に、v4 で追加した問題がちょうど8問ある(v4 の新しい項目の id を数える。v5 の用語は数えない)
  - 「くわしく」の網羅: チャートの形50・ローソク足50・用語120の全220項目に、空でない `detail` がある。`DETAIL_BY_ID` のキーは、既存の100項目(形とローソク足は最初の30種類、用語は最初の40問)とちょうど一致し、追加の用語80問と追加の形20種類と追加のローソク足20種類は含まない。これらは、自分の `detail` を持つ
  - 「くわしく」の質: 120〜250字、2〜4文、句点で終わる。220個がすべて違い、解説と同じ文・解説を含む文がない。「必ず」「絶対」「買うべき」「売るべき」を `detail` と `explanation` に含まない。チャートの形とローソク足の `detail` は「正解」「この問題」を含まない。`detail` が無い問題を `validateQuestion` が不備とする。形状の問題が、パターン定義の `detail` を使う
  - 追加の用語80問: id が重複せず既存の40問と重ならない。`category` が `term` か `technical` で、50問と30問。各難易度に用語10問とテクニカル6問があり、id の表と一致する。選択肢が4つで重複せず、解説が1〜2文。正解が選択肢の中で唯一いちばん長い問題は、全体で24問以内、各難易度で7問以内(現状は全体20問・各難易度の最大6問で、内容に依存する数)。どの項目から作った問題も `validateQuestion` を通り、難易度と `detail` を持つ
  - 難易度の表: 全パターン・全ローソク足・全用語に難易度が付き、種類ごとの個数が上の表のとおりである。
  - 難易度で絞ったデッキ: 問題がすべてその難易度で、重複がなく、同じシードなら同じになる。「全部まぜ」でも、同じ形の問題が同じラウンドに重ならない
  - 保存のキー: `statsKey` と `STATS_KEYS` が、難易度つきのキーを含む。難易度のない古い保存データは「すべて」として読め、壊れたデータは正しい部分だけ使う。結果のテキストに難易度の星が入る。値動き予想の古い保存キー(`outlook`、`outlook:hard` など)が残っていても、無視して読める
  - やり直しのデッキ: 間違えた問題だけが元の並びで入る。選択肢は入れ替わるが、集合と正解は変わらない。全問正解なら空で、やり直しの結果からさらに絞り込める
  - 移動平均線が短期10・中期30・長期60の3本である(生成の定数を含む)
  - 紛らわしい組が、正解の項目の問題の選択肢に同時に出ない(新しい組を含む。両方向で確かめる)
  - 新しいローソク足10種類と、新しいチャート10種類の定義を、数値で確かめる(窓の大きさ、はらみ十字の収まり、三法の内側、捨て子線の孤立、チャネルの傾き、Vの尖り、パーフェクトオーダーの並びと傾き、丸天井の対称、ダイヤモンドの振れ幅など)。チャートの形は、乱数のシード300〜500通りで確かめる
  - 追加した20種類のチャートの形の定義を、シード1〜300で数値で確かめる(ボックスの往復と水平さ、N字の3つの波、拡大三角形の高値と安値の広がり、ダマシの一時的な抜けと戻り、三角保ち合いの収束、リターンムーブの押し戻しの位置、ウェッジの収束、エリオット波動の波の関係(第3波が最大・第4波が第1波に重ならない・A・B・C の関係)、チャネルの平行と下抜け・上抜け、セリングクライマックスの加速)。しきい値は骨格から余裕をつけて決め、環境変数 `MARGINS=1` で最悪の余裕を、`SEEDS=5000` のようにシードの数を増やして確かめられる
  - 追加した20種類は、骨格が互いにはっきり違う(骨格を正規化して比べ、近すぎる組がない)。滑らかさ(隣り合う3点の折れ曲がり)は、追加分もこれまでと同じしきい値で、シード1〜300でも超えない
  - 追加した20種類の紛らわしい組が、両方向で `isConfusable` になり、形状の選択肢に同時に出ない。確認(v6)で足した14組も同じく確かめる(シード1〜60、両方向)。チャートの形どうしの組は計109組。`either` の形(三角持ち合い・拡大三角形・エリオット推進波の上・下)は続きの点線が空。各難易度の形状のラウンドが10問で、その難易度の10種類がちょうど1回ずつ出る
  - 追加したローソク足20種類の定義を、数値で確かめる(丸坊主のヒゲなし、寄り付き坊主の片側のヒゲ、四値同時線、三空の窓3回、並び赤・並び黒の始値のそろい、差し込み線・入り首線の終値の位置、行き違い線の始値と出合い線の終値のそろい、たすき線の始値の位置(前日の実体の中で、両端から 8 以上内側)と高値・安値の超えと値幅、放れの星の窓と小さな実体、赤三兵の先詰まりの上ヒゲと思案星の窓)。窓や食い込みは、画面で見える 8 以上の差で確かめる
  - 追加したローソク足20種類の紛らわしい組(61組)と、確認(v6)で足した3組が、両方向で `isConfusable` になり、選択肢に同時に出ない。ローソク足どうしの紛らわしい組は計97組。各難易度のローソク足のラウンドが10問で、その難易度の10種類がちょうど1回ずつ出る。追加の20種類は `DETAIL_BY_ID` に入らず、自分の `detail` を持つ

## 10. エラー処理

- `localStorage` が使えない場合(プライベートモードなど)は、保存をあきらめて、ゲーム自体はそのまま動かす
- 各モードに最低10問を用意し、難易度を指定しないとき1ラウンド10問が必ず成立するようにする。難易度で絞り込むと問題数が10問に満たないことがありうるが(現在は、チャートの形状・ローソク足・用語のいずれも、どの難易度でも10問以上ある)、どのモード × 難易度の組み合わせも1問以上を確保する(テストで問題数を確認する)。問題がない組み合わせのボタンは押せない状態にして「この難易度の問題は、まだないよ」と出す(現在は発生しない。念のための保護である)
- 「トップに戻る」の確認や、やり直しの開始のように、ダブルクリックで意図しない操作が起きうる画面では、描画直後の400ミリ秒間のクリックを無視する
